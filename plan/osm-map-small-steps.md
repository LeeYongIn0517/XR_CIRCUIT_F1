# OSM 지도 적용: 작은 실행 단계

각 단계는 Codex에 **하나씩** 입력한다. 결과를 검토한 뒤 다음 단계로 진행한다. 특별히 적지 않은 한, 작업 범위 밖의 서킷이나 화면은 수정하지 않는다.

## 진행 원칙

- 한 번의 명령에서 한 가지 결과만 만든다.
- 매 단계가 끝나면 변경 파일, 구현 내용, 확인 방법, 남은 문제를 보고받는다.
- 단계의 결과를 검토하기 전에는 다음 단계를 시작하지 않는다.
- 기존 FIA 지도 추적 자산의 권리 문제는 OSM 경로를 추가해도 자동으로 해결되지 않는다.
- 실제 앱의 지도 타일 제공자 약관과 출처 표시 방식을 확인하기 전에는 전체 서킷 데이터를 이관하지 않는다.

## 1단계 — 지도 엔진과 타일 제공자 조사

**Codex 실행 명령**

> `plan/osm-map-integration-plan.md`와 현재 프로젝트 구성을 확인해줘. 코드 수정 없이 Android·iOS에서 쓸 지도 엔진과 타일 제공자 후보를 비교하고, 라이선스·비용·오프라인 지원·현재 앱 UI와의 연결 방식을 표로 정리해줘. 아직 구현하지 말고 선택이 필요한 항목만 보고해줘.

**검토 기준:** 제공자 약관, 비용/요청 제한, ODbL 출처 표시, Android와 iOS 연동 방식을 확인한다. 이 단계에서 코드는 변경하지 않는다.

## 2단계 — Android 지도 바탕 시제품

**Codex 실행 명령**

> 앞서 정한 지도 엔진과 타일 제공자를 사용해 Android 서킷 상세 화면에 지도 바탕만 표시해줘. 트랙 경로·코너·섹터·DRS는 추가하지 말고, 수정 파일을 최소화해줘. 구현 후 변경 파일과 확인 방법을 요약해줘.

**검토 기준:** 지도 표시, 확대/축소, 이동, 화면 크기 대응을 확인한다. 트랙 오버레이는 아직 추가하지 않는다.

## 3단계 — Monza 경로 하나 표시

**Codex 실행 명령**

> OSM relation 284565를 기준으로 Monza 경로 데이터를 확인하고, 지도 위에 경로선 하나만 표시해줘. 원본 OSM 객체 ID와 버전을 기록하고 출처를 화면에 표시해줘. 기존 트랙 이미지나 다른 서킷은 수정하지 마.

**검토 기준:** OSM relation과 선택한 구성요소, 경로의 좌표·방향, 화면의 출처 표시를 확인한다. 다른 서킷 데이터는 수정하지 않는다.

## 4단계 — Monza 지도 정렬과 오류 상태

**Codex 실행 명령**

> Monza 경로가 지도 도로와 맞는지 확인할 수 있도록 초기 중심점과 줌을 조정해줘. 지도 로딩 실패와 네트워크가 없을 때의 표시도 추가해줘. 다른 서킷 데이터는 건드리지 마.

**검토 기준:** 경로와 지도 위치가 맞는지, 로딩 실패/오프라인에서 사용자가 상태를 알 수 있는지 확인한다.

## 5단계 — iOS에 Monza 시제품 연결

**Codex 실행 명령**

> Android에서 확인한 지도와 Monza 경로를 iOS SwiftUI 화면에도 표시해줘. 데이터 ID와 출처 표시는 Android와 일치시키고, 다른 서킷은 추가하지 마.

**검토 기준:** Android와 iOS에서 같은 경로 데이터와 OSM 출처가 보이는지 확인한다. iOS 전체 화면 개편은 하지 않는다.

## 6단계 — A등급 서킷을 세 개씩 추가

**Codex 실행 명령**

> 조사 결과 A등급 서킷 중 다음 세 개만 지도 경로로 추가해줘: `[서킷 이름 3개]`. OSM 객체와 시즌 기준을 기록하고, 각 경로의 연결·길이를 기존 앱 값과 비교해 결과를 보고해줘. 다른 서킷은 수정하지 마.

**검토 기준:** 한 묶음당 서킷 세 개만 추가한다. 각 경로의 OSM 객체 ID/버전, 길이 차이, 피트레인·대체 코스 포함 여부를 검토한 다음 다음 묶음으로 넘어간다.

## 7단계 — B등급 서킷 하나씩 검토

대상: Miami, Monaco, Red Bull Ring, Las Vegas, Lusail. 매번 한 서킷만 실행한다.

**Codex 실행 명령**

> `[Miami/Monaco/Red Bull Ring/Las Vegas/Lusail 중 하나]`만 검토해줘. OSM relation을 그대로 그리지 말고, F1 경로 후보와 분기·누락 구간을 지도에서 확인해 편집 필요 여부를 정리해줘. 이번 작업에서는 해당 서킷의 승인된 경로가 확정되지 않으면 앱에 노출하지 마.

**검토 기준:** relation에 다른 레이아웃·피트·일반 도로가 섞였는지 검토한다. 경로가 미확정이면 미노출 상태를 유지한다.

## 8단계 — Madring 공사/현행 경로 확인

**Codex 실행 명령**

> Madring OSM 경로의 공사 태그와 앱의 설계 데이터를 비교해줘. 현재 경로가 검증되지 않았다면 앱에서 어떻게 보류할지 제안하고, 승인 전에는 다른 서킷이나 화면을 수정하지 마.

**검토 기준:** 현행 레이아웃이 확인되지 않으면 정식 경로로 노출하지 않는다. 상태 표시 또는 보류 결정만 검토한다.

## 9단계 — 코너·섹터·DRS 레이어 추가

**Codex 실행 명령**

> 검수가 완료된 `[서킷 이름]` 하나에만 코너 번호와 섹터를 추가해줘. DRS 데이터는 출처와 시즌이 확인된 경우에만 표시하고, 지도 경로와 별도 레이어로 관리해줘.

**검토 기준:** 검수된 서킷 하나에서 코너/섹터 위치를 확인한다. 시즌과 출처가 확인되지 않은 DRS는 표시하지 않는다.

## 10단계 — 출시 전 출처·약관 점검

**Codex 실행 명령**

> 현재 지도 화면의 출처 표시, ODbL 안내, 타일 제공자 사용 조건, 번들된 경로 데이터 출처를 점검해줘. 미해결 항목과 출시를 막는 문제만 보고하고, 별도 요청 없이 대량 자산을 수정하지 마.

**검토 기준:** 지도 위 attribution 가림 여부, ODbL 고지/데이터 제공 방식, 타일 약관과 앱 수익화·요청량의 적합성을 확인한다. 권리 문제가 있는 기존 FIA 유래 자산도 별도 목록으로 확인한다.

## 실행 순서 요약

```text
1. 제공자 조사 및 결정
2. Android 지도 바탕
3. Monza 경로
4. Monza 정렬/오류 처리
5. iOS Monza
6. A등급 3개씩
7. B등급 한 개씩
8. Madring 보류/검증
9. 검수된 서킷의 추가 레이어
10. 출시 전 출처·약관 점검
```

각 단계의 구현 후 검토에서 문제가 발견되면 다음 단계로 넘어가지 말고 해당 단계만 수정한다.
